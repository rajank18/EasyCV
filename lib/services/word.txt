### **3. Notification Implementation Approach**

**Technology Used:** Flutter Local Notifications + SharedPreferences + Timezone

This project implements a sophisticated notification system with:
- **Local notifications** triggered at scheduled times
- **Smart message rotation** - messages never repeat until all are shown
- **Dual notification channels** for different purposes
- **Platform detection** (Android/iOS only, disabled on web)
- **User preference management** via Settings screen

**Why Local Notifications:**
- No dependency on external servers (Firebase Cloud Messaging)
- Works offline
- Precise scheduling control
- Privacy-friendly (no data sent externally)
- Immediate delivery at scheduled times

### **7. Smart Message Rotation Logic**

**Implementation:**
```dart
Future<String> _getRandomUnusedMessage() async {
  final prefs = await SharedPreferences.getInstance();
  final usedIndices = prefs.getStringList('used_notification_indices') ?? [];
  
  // If all messages used, reset the list
  if (usedIndices.length >= _notificationMessages.length) {
    await prefs.remove('used_notification_indices');
    return _getRandomUnusedMessage();
  }
  
  // Get available message indices
  final availableIndices = List.generate(_notificationMessages.length, (i) => i)
      .where((i) => !usedIndices.contains(i.toString()))
      .toList();
  
  // Pick random available message
  final random = Random();
  final selectedIndex = availableIndices[random.nextInt(availableIndices.length)];
  
  // Mark as used
  usedIndices.add(selectedIndex.toString());
  await prefs.setStringList('used_notification_indices', usedIndices);
  
  return _notificationMessages[selectedIndex];
}
```

**Key Features:**
✅ Messages selected randomly from available pool
✅ Once shown, message won't repeat until all others are shown
✅ Automatic reset when all messages exhausted
✅ Separate tracking for each notification type

### **8. Platform Detection**

**Implementation:**
```dart
bool get isNotificationSupported {
  if (kIsWeb) return false;
  return Platform.isAndroid || Platform.isIOS;
}
```

**Why Platform Detection:**
- Local notifications only work on mobile (Android/iOS)
- Web platform doesn't support flutter_local_notifications
- Prevents crashes on unsupported platforms
- All notification methods check this flag before executing

### **10. Screen Integration**

#### **A. Dashboard Screen** (dashboard_screen.dart)

**Purpose:** Automatically manage incomplete profile notifications based on profile status

**Implementation:**
```dart
Future<void> _checkProfileStatus() async {
  final user = _auth.currentUser;
  final doc = await _firestore.collection('users').doc(user.uid).get();
  
  if (doc.exists) {
    final isComplete = data?['profileComplete'] ?? false;
    
    // Handle incomplete profile notifications
    if (!kIsWeb) {
      if (!isComplete) {
        // Start daily notifications
        await NotificationService().scheduleDailyIncompleteProfileNotifications();
      } else {
        // Stop daily notifications
        await NotificationService().cancelIncompleteProfileNotifications();
      }
    }
  }
}
```

**Features:**

### **11. Notification Scheduling Details**

#### **Weekly Notifications:**
```dart
Future<void> scheduleWeeklyNotifications() async {
  final now = tz.TZDateTime.now(tz.local);
  var scheduledDate = _nextInstanceOfMonday(now);
  
  await _notifications.zonedSchedule(
    0, // Notification ID
    'EasyCV Reminder 📝',
    message,
    scheduledDate,
    details,
    matchDateTimeComponents: DateTimeComponents.dayOfWeekAndTime,
  );
}
```

**Schedule:** Every Monday at 10:00 AM
**Recurrence:** Automatically reschedules after firing

#### **Daily Incomplete Profile Notifications:**
```dart
Future<void> scheduleDailyIncompleteProfileNotifications() async {
  final now = tz.TZDateTime.now(tz.local);
  var scheduledDate = _nextInstanceOfTime(now, 9, 0); // 9:00 AM
  
  await _notifications.zonedSchedule(
    1, // Different notification ID
    'Complete Your Profile 👤',
    message,
    scheduledDate,
    details,
    matchDateTimeComponents: DateTimeComponents.time, // Daily
  );
}
```

**Schedule:** Every day at 9:00 AM (while profile incomplete)
**Auto-Cancel:** Stops when profile is completed

### **16. Technical Challenges & Solutions**

#### **Challenge 1: Web Platform Compatibility**
- **Problem:** `flutter_local_notifications` crashes on web
- **Solution:** Platform detection using `kIsWeb` and `Platform.isAndroid/iOS`

#### **Challenge 2: Message Repetition**
- **Problem:** Same message appearing repeatedly
- **Solution:** SharedPreferences tracking with automatic reset

#### **Challenge 3: Notification Persistence**
- **Problem:** Notifications lost after app restart
- **Solution:** Boot receiver in AndroidManifest + proper scheduling

#### **Challenge 4: Profile Status Synchronization**
- **Problem:** Notifications out of sync with profile status
- **Solution:** Check and update on dashboard load + profile save
